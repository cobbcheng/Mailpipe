## M0 实施顺序

1. 核对工具链、签名与系统支持范围。
2. 建立最小宿主与 Action 扩展。
3. 用合成邮件验证共享材料与正文重入。
4. 验证账户身份与有界定位。
5. 跑通单动作、读回、未知结果恢复与撤销。
6. 用合成内容验证两个受限 Adapter。
7. 记录数据，再冻结 P0 参数与目录结构。
8. 用合成库冻结只读查询契约。真机项 M0-11 至 M0-15 是 P1 历史搜索前置。

第 8 步不阻塞 P0 的身份与回执门槛。
它阻塞真实邮件库读取的实现。
不要先搭建完整漂亮 UI，再验证邮件写回。
不要用循环刷新 Mail 冒充异步动作接口。
不要为尚未观察到的并发失败先做通用锁。
方案见 [邮件集成](mail-integration.md) 第 10 节。

## 当前 P0 开发前置

P0 范围是 L0、L1、L2、单封数据去向标签，以及“要不要回复”分拣。
L2 是默认级别。验收落点只是菜单栏待处理。
发送只打开草稿。
这些能力尚未实现。
M0-16 未通过前，不把回复写入 Mail 草稿邮箱，也不把它算进 P0 验收。
M0-16 与 M0-17 仍未执行。
正文重入与退出重启的单样本实测已通过。
本机 MIME 提取已接入分拣和草稿。
HTML、multipart 和常见字符集会转成最多 16 KiB 的纯文本。
加密、仅附件、日历和畸形邮件仍待核对，并记下原因。
MailKit 上的真实邮件格式仍未验证。
单样本 UI 移动、宿主读回和移回已通过。
生产写回与并发冲突撤销通过前，仅提供移动建议。
用户在 Mail 中确认并手动移动。
宿主退出与 Mail 重启验收须在 P0 上线前完成。
它不阻止当前隔离开发。
证据见 [最新记录](validation/2026-11-16-m0-move-harness.md)。

## 退出与重评

| 失败 | 重评方向 |
|---|---|
| 身份无法可靠匹配 | L0 先做逐封建议。L1 与 L2 仍可留在待处理 |
| 账户查询成本过高 | 调整采集与索引，不默认全邮箱扫描 |
| 入站调用做不到零工具，或生成输出不止草稿 | 停止该 Adapter 的 L2，不改为开放工具 |
| 草稿邮箱实验失败 | 不阻塞 P0。继续用菜单栏待处理 |
| 只读库或 Spotlight 不可用 | 历史搜索保持不可用。P0 仍用 MailKit 与 Apple Events。不改写私有库，也不默认全盘访问 |
| 条款不允许 | 调整接入或产品前提，不能用技术可调用代替 |
| 分拣误报过高，或用户不用主动回复 | 默认降到 L1。不把分类准确率当作完成 |

P2 自动发送不属于这些阶段的默认实施任务。
