## M0 实施顺序

1. 核对工具链、签名与系统支持范围。
2. 建立最小宿主与 Action 扩展。
3. 用合成邮件验证共享材料与正文重入。
4. 验证账户身份与有界定位。
5. 跑通单动作、读回、未知结果恢复与撤销。
6. 用合成内容验证两个受限 Adapter。
7. 记录数据，再冻结 P0 参数与目录结构。

不要先搭建完整漂亮 UI，再验证邮件写回。
不要用循环刷新 Mail 冒充异步动作接口。

## 退出与重评

| 失败 | 重评方向 |
|---|---|
| 身份无法可靠匹配 | 先做逐封建议；重新评估自动整理 |
| 账户查询成本过高 | 调整采集与索引，不默认全邮箱扫描 |
| Harness 无可靠受限模式 | 暂停该 Adapter，不绕过安全边界 |
| 条款不允许 | 调整接入或产品前提，不能用技术可调用代替 |
| 用户不使用规则 | 缩小规则面，强化开箱分类与纠错 |

P2 自动发送不属于这些阶段的默认实施任务。
