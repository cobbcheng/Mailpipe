# 隐私、权限与安全

状态：设计约束，尚未安全验收。
更新：2026-11-19。

## 1. 信任边界

```text
不可信邮件 / 附件
    ↓ 有界解析与清洗
本地账户身份与用户授权
    ↓ 最小输入 + 固定 schema
受限 Harness（实际推理由其配置决定）
    ├─ 入站：直接起草。可读取来信引用的首个公开 GitHub PR 差异
    └─ 用户主动：只能调用 Mailpipe 工具
Mailpipe 校验检索结果或动作意图
    ↓ 结构化结果，不含可执行脚本
规则校验与动作计划
    ↓ 持久意图 + 当前状态检查
固定 MailBridge 操作
    ↓ 读回回执
用户可检查与条件撤销
```

起草时从应用资源加载[邮件回复规则](../Packages/HarnessAdapters/Sources/Resources/reply-policy.md)，注入 Harness 系统提示。
邮件中的指令不构成用户授权。
不可信来信不能驱动 Agent。
工作台按已授权的来信直接生成草稿。
宿主为每次起草绑定一个 PR 地址。
MCP 读工具不接收模型提供的地址或命令。
自动起草使用 GitHub 公开接口。
重新生成时，用户可确认使用本机 GitHub 账户读取该 PR。
工具最多返回前 30 个文件、共 32,000 个 UTF-16 码元的差异。
处理说明按工具回执展示是否取得差异。
生成调用的输出只能是草稿。
邮件不能创建规则、改变路由、打开撰写窗口或触发发送。
发送只打开草稿，不调用 send。
格式校验不防止所有语义攻击；还需动作边界。

## 2. 权限矩阵

| 能力 | 何时说明 / 请求 | 拒绝后的行为 |
|---|---|---|
| Mail 扩展 | 引导时让用户手动启用 | 无自动新邮件采集 |
| 正文访问 | Mail 扩展实际请求时说明 | 仅元数据，不能假装完整摘要 |
| Apple Events | P0 自动整理或读取 Mail 选择前 | 停止依赖该权限的读取与修改 |
| 通知 | P1 用户设置摘要提醒时 | App 内显示 |
| 文件选择 | 用户添加草稿附件时 | 不添加附件 |
| 历史邮件库只读 | 用户开启历史搜索时，预选 Mail 库文件夹 | 无历史搜索；其他功能仍可用 |
| 完全磁盘访问 | 不默认申请 | 不改用它绕过文件夹授权被拒绝 |
| 联系人 | 初版不申请 | 用户输入地址或使用原邮件地址 |
| 辅助功能 | 不申请 | 不用 UI 脚本补搜索或回写 |

取舍见 [邮件集成](mail-integration.md) 第 10 节。
预选文件夹是历史搜索的默认授权。
完全磁盘访问只在该方式被验证为不可用后另作决定。
辅助功能不因为竞品使用而申请。
观察记录见第 9 节。`Library/Accounts` 仍是未采纳的 [Q-17](known-issues.md)。

Apple Events 权限是系统授权。
账户范围、规则和动作许可仍由 App 自行约束。
自动化授权不代表可以发送，也不代表可以读私有库。
历史读取必须另有用户授权。

## 3. 威胁与控制

| 威胁 | 必须具备的控制 | 验证 |
|---|---|---|
| 邮件要求读文件或发网络请求 | 禁止内置 shell、文件工具和任意 MCP | 注入 canary；检查实际副作用 |
| 来信驱动 Agent | 入站调用无工具权限；生成输出只能是草稿 | canary 不能产生工具调用、移动或发送 |
| 模型要求读完整邮件库 | 工具只返回有上限的命中 | 夹具超过上限时必须截断 |
| 模型要求写私有库或直接改 Mail | 写工具只产生意图；无写库工具 | 夹具文件哈希不变 |
| 模型伪造动作 | schema 无自由动作；执行器固定白名单 | 非法字段与枚举测试 |
| 路由回退泄露 | 每账户 allowlist，未知账户不自动外发 | 敏感账户回退测试 |
| 相同 Message-ID 改错邮件 | 账户绑定与唯一定位 | 跨账户重复样本 |
| 脚本参数注入 | 类型化参数，不拼脚本或 shell | 引号、换行、命令文本样本 |
| MIME 资源耗尽 | 原文 4 MiB，深度 8，部分 64，模型正文 16 KiB | 大附件、嵌套 MIME、畸形编码 |
| HTML 追踪 | 不执行 HTML，不下载远程资源 | 追踪链接与隐藏文本样本 |
| 用户改动被覆盖 | 写前 / 撤销前检查目标字段 | 并发手动移动、已读测试 |
| 草稿发错人 | 收件人来源校验、显式预览 | Reply-To 改域、地址歧义 |
| 重启重复写 / 发 | 意图与回执核对；P1 无 send | 中断点测试与调用记录 |

内容清洗不是可靠的提示注入防护边界。
固定工作目录不是文件沙盒。
只读模式也不等于禁止读取秘密。
安全模式无法证明有效时，禁止真实邮件调用。

## 4. 数据去向与表述

P0 要求单封数据去向标签。
每封交给模型的邮件标明 Harness、模型厂商和证据来源。
设置与状态栏仍显示当前路由。
单封标签回答的是这一封实际发给了谁。
信息必须标注来源：检测、用户声明或未知。
用户声明本地不等于 App 已验证本地。
检测结果不能决定放宽账户权限。

允许文案：“收信即备好回复，邮件不经我们的服务器”。
必须同时说明：调度在这台 Mac 上，内容仍会交给所选 Harness 的模型厂商。
允许文案：“邮件交给你选择的 Harness”。
必须补充：“数据去向由其配置决定”。
禁止无证据声称“邮件不离开本机”。
禁止声称“全部在本地发生”或“端侧 AI”。
无自建服务器不等于无第三方云端处理。
Mailpipe 不新增云端副本，也不做中间转发。

历史搜索只发送该次命中的少量内容，不发送全库。
Harness 使用云端模型时，这些命中会离开本机。
搜索界面必须重复这句话。
去向未知时显示未知，不写成留在本机。
去向未知时可以本地展示命中。
未确认前不把命中自动交给模型。
账户未知的命中同样不自动外发。

App 不保存模型 API Key，不读取认证文件。
Harness 自身会话、日志和云端保留政策单独提示。
删除 Mailpipe 数据不代表删除这些副本。

## 5. 本地数据与诊断

私有数据落在用户专用目录或 App Group。
文件权限限制为所需进程和当前用户。
不把正文放入命令行参数或通用日志。
stdout 仅在内存中有界解析，不默认落原文。
错误诊断保存错误码、版本、阶段和耗时。
邮件主题、地址、正文和附件名默认不进入诊断。

初版不采集遥测。
后续若增加遥测，另定字段与用户许可。
日志加密方案尚未实现，不宣称应用级加密。
系统磁盘加密状态不能替代 App 自身安全验收。

## 6. 暂停、撤权与清除

暂停立即阻止新派发和新 Mail 操作。
取消在途推理，并丢弃迟到结果。
已经发出的 Mail 操作只做收尾核验。
恢复需要用户主动操作，重查策略版本。

权限撤销后不反复弹窗。
不得改用辅助功能、全盘访问、SMTP 或其他 Harness 绕过。
历史读取授权被拒绝后，不改读其他目录。
清除数据流程见 [数据契约](data-contracts.md)。

## 7. P1 / P2 发送边界

入站默认级别是 L2，属 P0。
草稿进入菜单栏待处理。
Mail 草稿邮箱要等实机验证，未通过前不写入。
不自动打开撰写窗口。
发送只打开草稿，不提供 send 入口。
“已备好”和“已交给 Mail”都不能改写为“已发送”。
占位符提示只能保证交接前检查。
不保证能检查用户在 Mail 中修改后的正文。

P2 的 L3 是白名单延迟自动发送，尚未定稿。
必须另行授权，并另行定义收件人、模板、预算和撤回窗口。
必须有发送日志。
撤销只发生在发出前，不承诺发送后撤回。
不得因系统已有 Apple Events 权限自动开放发送。
不得因已有草稿或历史读取授权自动开放发送或永久删除。

Agent 发起的写操作确认：

| 操作 | 确认 |
|---|---|
| 单封移动、已读、旗标 | 展示前后值，确认该意图 |
| 批量，或移到废纸篓，或新建邮箱 | 单独确认数量、账户和目标 |
| 永久删除 | 不提供 |
| 发送 | L2 与 P1 都不提供。L3 另授权 |

已保存规则对未来新邮件的授权不因本表消失。
批量撤销逐条报告，沿用条件撤销。
冲突时不覆盖用户后来的修改。

## 8. 发布门槛

安全用例必须验证实际副作用，不只检查参数。
检查零非授权文件读取、零内置工具执行、零私有库写入和零发送。
订阅与第三方自动化条款核验尚未完成。
未通过的 Adapter 不进入自动整理发布名单。

## 旧版手动来信的授权边界

旧版手动来信的单封许可仅对应当时确认的内容和工具。
已有草稿保留在本机。
要处理新来信，原手动模式的用户须确认扩展、来信范围与 Agent。

## 新邮件来源证据

build 11 为新采集保存来源证据。
先核对唯一授权账户，再使用完整原文。
证据包含稳定头字段及完整 MIME 正文摘要。
附件和嵌套部分也必须匹配。
已采集的 MIME 参数不得变化。
恢复的参数仅来自已核验的完整原文。
详细字段与失败边界见 [邮件集成](mail-integration.md)。
旧记录不自动重试，不仅凭主题或 Message-ID 认定账户。
恢复来源证据同样遵守当前授权与暂停状态。
