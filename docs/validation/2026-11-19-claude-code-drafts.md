# Claude Code 普通草稿验收

2026-11-19，签名菜单栏 App 通过合成草稿验收。
系统为 macOS 27.0.1，SDK 为 27.2。
候选宿主和扩展为 0.0.5（build 32）。
两者均使用 Apple Development 签名。
严格签名检查通过，权限与本机安装包一致。

## 菜单栏实测

使用独立队列和本机 Claude Code 2.1.296。
模型由 CLI 选择，App 未传入模型名。
合成回调仅授权一个完整主题。未使用邮箱账户。

| 操作 | 观察到的结果 |
|---|---|
| 点击菜单栏「继续设置 Mailpipe」，选择 Claude Code 并点击连接 | 引导显示工具与实际模型。固定样例生成草稿，单独存入测试队列 |
| 退出候选 App，在隔离目录使用已通过的试写记录激活限定主题授权 | 通过生产采集入口注入一封合成 MIME 来信。回调文件数为 1 |
| 重开候选 App，等待普通来信队列处理 | SQLite 状态为 draftReady，菜单显示该主题和 1 份未读草稿 |
| 点击菜单栏的合成来信 | 工作台显示来信、可编辑回复及数据去向。工具为 Claude Code，模型为 deepseek-v4.1-flash |
| 重启候选 App，再次打开同一封来信 | 旧草稿可读。点击重新生成并确认，新增一次运行，新草稿可编辑 |

初次普通草稿出现来信未提供的署名。
适配器补充了省略无来源署名的要求。
复测草稿省略署名，但主动提出后续审阅。
这项承诺仍需用户审阅。

系统 MailKit 扩展的投递、真实邮箱与 Mail 撰写窗口未验证。
隔离目录的最终授权由测试助手调用宿主 API 完成。
本次没有发送邮件或覆盖已安装的 App。
