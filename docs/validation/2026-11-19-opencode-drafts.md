2026-11-19，OpenCode 2.3.0 完成两次云端合成起草。
系统为 macOS 27.0.1，SDK 为 27.2。
候选宿主与扩展均为 0.0.5（build 32）。
Apple Development 签名通过严格校验。
宿主、扩展的权限分别与本机安装包一致。

## 从选择工具到打开草稿

| 操作 | 实际结果 |
|---|---|
| 从候选 App 菜单栏打开引导并选择 OpenCode | 能发现原生安装路径，并指定供应方和模型 |
| 用免费模型试写 | 服务返回额度不足。界面显示失败，正式队列未获授权 |
| 用户另行授权临时测试配置，显式切换至 DeepSeek v4.1 Flash | 真实 OpenCode 完成试写，引导显示经过核对的完整模型名 |
| 在隔离队列激活单一完整主题的授权 | 通过生产采集函数投递一封合成 MIME，产生一个回调文件 |
| 重开候选 App 并从菜单栏点击合成来信 | 普通队列生成并持久化草稿。工作台可编辑，数据去向显示 OpenCode 和授权模型 |

## 隔离边界

每次使用独立服务器、临时 HOME、目录和会话库。
App 让 OpenCode 自行加载原生提供商配置。
适用范围为单份用户 JSON 或 JSONC 配置，或免登录模型。
只保存在个人会话库的登录态、依赖个人插件的模型尚未支持。
受管理的配置可能覆盖权限设置，当前不接受此类环境。

用户可从 `opencode models` 选择 `provider/model`。
空输入仅允许固定示例使用隔离环境的默认模型。
原生环境和隔离环境的默认选择可能不同。
普通来信固定使用试写回执中的供应方和模型。
切换目标会使试写证据失效，并要求重新授权。
固定标题避免为邮件另发一次标题生成请求。
从临时库仅读取对应助手消息的模型回执。

同一台机器上的本地模拟服务检查了实际请求内容。
对照模式会启动配置的插件和 MCP，并附带个人指令。
受限模式下，两者未启动，个人指令未出现。
请求包含 Mailpipe 回复规则，向模型公开的工具数为零。
两次对照请求均在本机完成，外部模型调用为零。

隔离回归通过 102 项，真实 Harness 调用日志为空。
其中运行时 67 项、适配器 30 项、回复契约 5 项。
范围包括拒绝未绑定模型、撤销旧队列授权、
拒绝工具事件及交叉会话回执，并验证分项 token 加总。
