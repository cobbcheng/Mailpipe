## 正文实验实现

入口位于宿主的“M0 身份验证”。
选择“授权 15 分钟合成正文实验”。
主题和正文标记由当前会话生成。
仅精确主题匹配的 received 回调可进入实验。
旧版元数据授权不会自动升级为正文授权。

无 rawData 时，先落盘请求记录。
成功后才返回 `invokeAgainWithBody`。
同会话后续无正文回调不再次请求。
扩展重启后仍读取同一请求记录。
请求落盘后若崩溃，本会话可能没有回调。
此时需核对结果，不能自动重放。

这是一次合成会话的一次请求上限。
不是生产队列，也不是通用后台重试。
所有者是扩展，触发是授权后的匹配回调。
外部效果仅为请求 Mail 再次提供正文。
每次正文实验产生一个小型请求记录文件。
本轮未新增后台清理机制。

有 rawData 时，只在内存检查合成标记。
仅接受不超过 64 KiB 的明文 UTF-8 夹具。
按 MIME 头体分隔符检查正文部分。
不把“头字段含标记”当成正文成功。
回执仅存时间、会话、字节数和命中布尔值。
原始内容、地址和附件不落入回执。
这不是通用 MIME、HTML 或附件处理实现。

API 依据为 [Apple 的回调说明](https://developer.apple.com/documentation/mailkit/memessageactionhandler/decideaction(for:completionhandler:))。
在线示例使用 `bodyData`，当前 SDK 使用 `rawData`。
代码以当前 SDK 头文件及编译结果为准。
接口声明不证明本机发生过正文重入。

## 待执行的实机步骤

先按 [部署方法](../deployment.md) 核对签名和目标环境。
使用明确指定的测试账户与合成内容。
原始回执留私有目录，共享报告只保留脱敏结论。

| 实验 | 步骤 | 通过证据 |
|---|---|---|
| 正文重入 | 开始正文会话；投递匹配主题及标记的明文合成邮件 | 先有 body_requested 日志，再有标记命中回执 |
| 正文已就绪 | 记录首次回调已有 rawData 的情况 | 单独记录，不冒充两阶段重入 |
| 撤权 | 请求正文后停止会话，再观察迟到回调 | 不产生当前有效回执或动作 |
| 移动 | 核对源邮箱唯一命中；持久记录意图；移入指定测试目录 | 源缺失、目标唯一命中；记录前后本地 ID 和 Message-ID |
| 移回 | 核对目标唯一命中和当前状态；记录撤销意图；移回 | 原目录唯一命中，目标缺失，回执与意图关联 |
| 身份歧义 | 目标已有相同 Message-ID | 拒绝自动选择；零错误目标写入 |
| 用户冲突 | 移动后用户再次改变位置 | 撤销拒绝覆盖，不自动全账户搜索并写入 |
| 宿主退出 | 授权后正常退出宿主，再收一封匹配合成邮件 | 扩展独立产回执；重开宿主可读取 |
| Mail 重启 | 正常退出并重开 Mail；有效会话内收新合成邮件 | 新回调与回执；没有旧动作重放 |
| 撤权后重启 | 停止会话再重启 Mail 与宿主 | 旧授权不恢复，没有新有效回执 |

发送测试邮件需独立明确收件目标。
现有邮件的显示或刷新不代替新邮件回调。
出现未知移动结果时先读回，不再次执行移动。
手动移动成功仅证明实验路径。
它不证明 App 的动作账本和撤销执行器已实现。
