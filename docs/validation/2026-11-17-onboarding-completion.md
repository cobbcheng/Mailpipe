# 引导补齐验证

日期：2026-11-17。
基线：`977c4b4`；实现见本记录所在提交。
App：0.0.1，build 7。
范围：扩展证据、分级测试、拒绝后逐封建议。

## 方案与边界

| 问题 | 实现 | 限制 |
| --- | --- | --- |
| 只靠用户勾选 | 扩展写事件、时间和版本；宿主读回 | 只证明历史运行，不证明当前仍启用 |
| 无设置页入口 | 打开 `mail-pref-pane://extensionspref` | 非公开稳定 API；保留手动路径 |
| 低级别依赖 L2 | 测试前选级别，完成条件按级别检查 | 固定样本须分拣为 yes |
| L1 完成文案不一致 | 使用规格中的“提示需要回复的邮件” | 不生成草稿 |
| 拒绝后无退路 | 粘贴一封、预览、确认工具后派发 | 不读取 Mail，不建立自动账户映射 |

未增加重试、锁或后台服务。
逐封任务复用现有宿主队列与持久化状态。
用户确认是唯一触发，UUID 是意图幂等键。
同一意图重复提交不重放调用。
策略版本、暂停、撤权在调用前后重查。
在途未知结果沿用待核对，不自动重试。
外部效果仅限确认内容的受限模型调用。
没有 Mail 写入或发送。

## 隔离自动回归

命令：

```sh
./scripts/test.sh --filter 'Onboarding|PipelineTests|ManualSuggestionTests|ExtensionObservationTests|ReplyProbeTests'
```

30 项测试通过，真实 Harness 调用日志为空。
使用临时目录、fake model 和 fake Mail resolver。
不连接真实模型、邮箱或消息通道。

| 覆盖 | 结果 |
| --- | --- |
| L0/L1/L2，自动及逐封两种模式 | 分别 1/1/2 次 fake 调用，均可完成 |
| 切换工具或级别 | 旧测试关联失效，不自动重跑 |
| 合成分拣为 no/unknown | 不冒充所选级别验证通过 |
| 切换到逐封模式 | 清除自动范围、保留暂停 |
| 未确认、超限、错误工具、入站伪造授权 | 拒绝，零 fake 调用 |
| 重复确认同一意图 | 仅一次处理，不访问 Mail resolver |
| 暂停、撤权、切换工具 | 阻止后续派发 |
| 分拣期间撤权 | 保留用量，不进入草稿阶段 |
| 回执缺失、过期、未来、损坏 | 不显示有效运行证据 |
| 原有队列、账户唯一匹配与受限 Adapter | 受影响测试通过 |

## 原生界面集成

在独立应用身份、临时数据目录运行。
仅指定 fake `dsh`，未选用真实工具。
UI 合成主题与正文仅使用 `example.com`。

1. L1 显示一次分拣测试，运行后通过。
2. 未启用扩展即可主动选择逐封建议。
3. 无账户选择、无共享容器也可完成逐封引导。
4. 工作台可粘贴、预览并确认一封。
5. 结果进入“需要回复”，没有草稿阶段。
6. 退出、重启后结果保留，没有新增调用。
7. 点击“我已操作”而无回执，仍显示待验证。
8. 修正后的设置按钮直接打开 Mail“扩展”页。
