# 菜单栏打开工作台

2026-11-19，本机签名 build 20 已通过点击验收。

## 卡顿与修复

build 19 主线程采样覆盖了两条慢查询。
后台队列同步等待收件箱核验。
工作台可见行同步等待旧邮件地址补齐。
等待 Apple Mail 期间，界面无法及时处理点击。
工作台打开后，菜单弹窗还会遮住窗口。

宿主现在按需启动同一签名程序的只读子进程。
AppleScript 在子进程主线程执行。
每次查询增加一次本机进程启动。
查询串行执行，参数和结果通过有界管道传递。
子进程只接受同一宿主发起的读取。
超时沿用现有失败处理；子进程不打开队列。

宿主仍负责核验来源、账户与处理范围。
等待结束后重新检查授权与当前记录。
菜单选择来信或打开工作台时会收起弹窗。

## 验证范围

| 环境 | 操作 | 结果 |
|---|---|---|
| 临时目录与假工具 | 延迟返回、取消排队、读取大于管道容量的结果 | 单个查询等待时主线程仍可处理事件 |
| 临时队列 | 查询期间编辑、丢弃、取消、暂停或换授权 | 迟到结果保留用户操作，旧记录不会查询新授权账户 |
| 签名 App 与合成记录 | 分别点击打开工作台、菜单最近项 | 弹窗关闭，最近项选中正确的合成记录 |
| 本机安装包 | 后台查询期间从菜单弹窗点击打开工作台 | 约 0.32 秒后确认工作台在前台，弹窗已关闭 |

实机使用 macOS 27.0.1、macOS SDK 27.2。
沿用现有账户的收件箱授权。账户服务商未核验。
安装前已确认队列无在途派发，并私有备份旧包与数据。
宿主与扩展均保留原签名、权限及双架构。
核对时设置、既有草稿和模型运行记录一致。

Runtime 和 MailBridge 共 78 项隔离测试通过。
真实 Harness 保护日志为空。
实机验证期间未新增模型调用，也未发送邮件。

## Build 21 清理重装

排队读取现在会在启动子进程前复核当前授权。
已撤销的正文读取和收件箱核验均在队列内结束。
暂停或撤权也会取消正在等待核验的配置保存。

- Runtime 和 MailBridge 共 79 项隔离测试通过。
- 模拟两条读取排队后撤权，仅首个子进程启动。
- 在空的安装位置放入全新签名构建。
- 宿主和扩展均为 build 21，严格签名校验通过。
- 系统查询只返回安装目录中的宿主和一个启用的扩展。
- 实际点击后约 0.34 秒确认工作台在前台，弹窗已关闭。
- 设置、历史草稿与运行记录一致，新增模型调用为零。

## Build 22 的 Dock 图标

build 21 的每次只读查询都会启动同一宿主程序。
系统把宿主与读取子进程都登记为普通应用。
实机同时检测到多个运行中的 Mailpipe Dock 项。

build 22 通过 `LSUIElement` 让程序以后台身份启动。
只有进入工作台的宿主才切换为普通应用。
读取子进程保留后台身份。参见 [Apple 的 LSUIElement 说明](https://developer.apple.com/documentation/bundleresources/information-property-list/lsuielement)。

本机安装后从菜单栏点击「打开工作台」。
约 0.43 秒后确认工作台在前台，弹窗已关闭。
3 项只读桥接隔离测试通过。
原有设置、草稿和运行记录核对一致。

30 秒内取得 277 次有效 Dock 采样。
期间观察到 19 个查询子进程，均无普通应用身份。
每次采样都只有一个运行中的 Mailpipe Dock 图标。

## Build 24 的 Dock 重开

build 23 中，Dock 图标指向已安装的宿主。
关闭工作台后点击图标，窗口数仍为零。
build 24 将 Dock 重开事件接到现有工作台窗口。

| 环境 | 操作 | 结果 |
|---|---|---|
| 隔离队列，已完成引导 | 从退出状态启动宿主 | 工作台取得前台焦点 |
| 本机安装包 | 关闭工作台，再点 Dock | 重新打开一个工作台 |
| 本机安装包 | 最小化工作台，再点 Dock | 恢复窗口并取得焦点 |
| 本机安装包 | 隐藏宿主，再点 Dock | 工作台回到前台 |
| 本机安装包 | 工作台打开时重复点击 Dock | 始终只有一个工作台 |
| 本机安装包 | 点菜单栏图标，再选「打开工作台」 | 弹窗关闭，工作台取得焦点 |

实机使用 macOS 27.0.1、macOS SDK 27.2。
宿主与扩展均通过签名、权限及双架构核验。
升级前后队列、运行记录和采集授权一致。
3 项只读子进程隔离测试通过。
