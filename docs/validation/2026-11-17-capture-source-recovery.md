# MailKit MIME 参数丢失修复验收

日期：2026-11-17。
代码提交：`c60bd55`。
独立分支：`codex/capture-plain-text`。
结论：限定样本的隔离回归与实机链路通过。
普通纯文本及双正文邮件均能完成 fake 备稿。
真实模型质量、广泛邮箱兼容仍未验证。

## 失败证据

用户报告普通文本邮件被拒绝。
界面原因是 `malformedMIME`。
当时的原始采集已删除，不能追溯具体字节。
完整原文单独解析通过。

随后使用新合成邮件复现两条路径。

| 输入 | MailKit 数据 | 完整原文 | 修复前结果 |
|---|---|---|---|
| Google → Microsoft 中文纯文本 | Content-Type 缺少 charset | 保留 UTF-8 参数 | unsupportedCharset |
| Google → Microsoft 双正文 | Content-Type 缺少 boundary | 保留 multipart 边界参数 | malformedMIME |

Microsoft 邮箱在 Mail 中标记为 Exchange。
两条路径的完整 MIME 正文传输字节相同。
MailKit 还会改写显示名、头字段顺序和折行。
因此整封规范化原文摘要也不能直接相等。

这是本机限定路径的实测结果。
不把差异归因于所有 Gmail 或所有 MailKit 版本。
原报告与复现路径一致，但原始失败字节未保留。

## 实质方案

| 方案 | 限制 | 结论 |
|---|---|---|
| 猜 charset 或从正文猜 boundary | 不能解决来源摘要不一致 | 不采用 |
| 只按 Message-ID 与主题读完整原文 | 不能排除内容冲突 | 不采用 |
| 稳定头字段加完整 MIME 正文核对 | 复杂地址语法暂不支持 | 采用 |

新采集由宿主生成 `MailSourceEvidence`。
发件人、收件人和回复地址须一致。
日期、主题、Message-ID 和引用头须一致。
MIME 类型、传输编码与 Disposition 须一致。
完整 MIME 正文摘要包含附件和所有子部分。
已采集的 MIME 参数不能被新来源覆盖。
地址显示名、传输头与折行不作为身份差异。
详细规范见 [邮件集成](../mail-integration.md)。

账户核验仍仅在当前授权范围内执行。
Message-ID、主题与来源证据须唯一匹配。
匹配后才从完整原文提取模型正文。
来源缺失、变化或歧义均不调用模型。
旧记录和证据不足的记录仍使用旧摘要核验。

所有者是宿主既有账户核验阶段。
触发是新入站拥有足够来源证据。
沿用每个授权范围一次查询和现有上限。
未新增重试、锁、后台机制或 MailKit 重放。
入站 ID 保持幂等；中断状态不自动重放。
原有失败记录没有重新处理。
