# 产品方案

状态：基于 PRD v0.5 的工程化草案，与 Notion PRD 对齐。
更新：2026-11-16。来源见 [来源](sources.md)。
本文件不替换或修改原 Notion 文档。
定位、服务级别和单封数据去向标签已由产品负责人确认。
其余未标明“用户已确认”的优先级调整仍是建议。
那些建议尚未经产品实测。

## 定位

Mailpipe 不是分类或摘要工具。
Harness 已经能做好分类、摘要和回复。
核心价值是两条：本地优先，以及主动服务。

一句话：收信即备好回复，邮件不经我们的服务器。

本地优先指本地编排。
调度与执行发生在用户的 Mac 上。
Mailpipe 不新增云端副本，也不经中间服务器转发。
邮件内容仍会发给用户 Harness 所使用的模型厂商。
不声称“全部在本地发生”，也不声称“端侧 AI”。

主动服务的默认结果是备好回复。
对外说法是“打开 Mac 时，回复已经备好”。
不承诺 24 小时即时回复。

## 主动服务级别

| 级别 | 行为 | 落地 | 授权 |
|---|---|---|---|
| L0 | 静默整理 | 只执行已授权的整理，不提示回复 | 沿用账户与动作授权 |
| L1 | 提示“这封需要回复” | 出现在菜单栏待处理列表 | 不生成草稿，不打开窗口 |
| L2 | 备好草稿（默认） | 菜单栏待处理列表，或 Mail 草稿邮箱 | 不自动打开撰写窗口，不发送 |
| L3 | 白名单延迟自动发送 | 发出前写日志，发出前可撤销 | P2，单独授权 |

默认级别是 L2。
L0 到 L2 是处理强度，不是功能灰度开关。
L3 不复用 P1 或 L2 的授权。
待处理列表不是 Mail 旗标。
草稿邮箱里放的是回复草稿，不是排队旗标。
AppleScript 草稿能否留在原线程并同步到 iPhone，未验证。
未验证前，菜单栏待处理列表是确定的落点。

## 问题与目标

| 问题 | 用户结果 |
|---|---|
| 新邮件来了才开始写回复 | 打开 Mac 时，该回复的邮件已经有草稿 |
| 邮件若再经一层服务器，去向说不清 | 不经 Mailpipe 的服务器；每封标明实际厂商 |
| 分类和摘要本身不再构成差异 | 只用来判断要不要回复，以省额度、减少误报 |

首要用户：已使用 Harness 的技术型 Mac 用户。
次要用户：已装 Harness 的高邮件量用户。
不面向尚未配置 Harness 的大众市场承诺开箱即用。

## 范围与验收

| 级别 | 能力 | 验收结果 |
|---|---|---|
| P0 | 新邮件采集与恢复 | 宿主重启后接续；重复回调不重复执行 |
| P0 | 两个 Harness Adapter | 分别验证无头、受限模式、结构化输出 |
| P0 | 单封数据去向标签 | 标明该封交给了哪个 Harness 与模型厂商；未知显示未知 |
| P0 | 回复分拣 | 分类与摘要只作为“要不要回复”的输入；分拣先于草稿 |
| P0 | 默认 L2 草稿 | 进入菜单栏待处理或 Mail 草稿邮箱；不自动打开撰写窗口；不发送 |
| P0 | 自然语言规则 | 保存前预览；语义不支持时明确拒绝 |
| P0 | L0 自动整理 | 仅授权账户；唯一定位；执行后读回 |
| P0 | 日志与条件撤销 | 看见原值、新值、规则与结果；冲突不覆盖 |
| P0 | 账户路由与暂停 | 禁止未授权回退；暂停后无新动作 |
| P0 | 签名直装 | 在干净测试环境验证安装与权限 |
| P1 | Daily Digest | 有覆盖区间与缺口；可定位来源 |
| P1 | 用户主动起草 | 用户点名后才生成；仍不调用 send；不替代默认 L2 |
| P1 | 历史邮件全量读取与 Agent 查找 | 用户已确认。可选授权；按查询只读；只提交命中片段 |
| P1 | Agent 增删改查 | 用户已确认。只产生意图；读回后才算完成；不调用 send |
| P1 | 更多 Adapter | 按版本建立独立安全验收 |
| P1 | 用量面板 | 调用、耗时、失败分开；缺失 token 显示未知 |
| P2 | L3 白名单延迟自动发送 | 另立设计；有日志和发出前撤销；不复用 L2 授权 |
| P2 | 日历、待办、规则分享 | 尚未设计，不作为当前交付 |

分类仍用两个维度，但只作为分拣输入。
`category` 是客户、账单、通知、Newsletter、其他。
`needs_action` 独立表示需要行动。
分拣要回答“要不要回复”。
类别和摘要不能单独触发草稿或发送。
“待回复”是分拣视图，不与业务类别互斥。
模型无法判断时输出 `unknown`，不生成草稿。

## 触发与额度

| 限制 | 口径 |
|---|---|
| MailKit 只在 Mail 运行并下载新邮件时回调 | Mail 没在跑时不会处理 |
| 合盖 | 不承诺处理。说“打开 Mac 时，回复已经备好” |
| 睡眠与 Power Nap | 期间是否仍会回调，未验证。验证前不写成能力 |
| 每封进入处理的新邮件 | 至少一次 Harness 调用，占用用户自己的订阅额度 |
| 分拣未通过 | 不再生成草稿，避免多消耗一次额度 |

不把合盖或睡眠说成 24 小时在线回复。

## 与 PRD v0.5 的对齐

本文件的定位、服务级别和 P0 数据去向标签与 PRD v0.5 一致。
下表相对 v0.3 的定位变化，已由产品负责人确认。

| v0.3 | v0.5 | 原因 |
|---|---|---|
| 分类、摘要和整理是首要价值 | 收信即备好回复；分类和摘要降为分拣输入 | Harness 已能做好分类、摘要和回复 |
| 本地容易被说成端侧推理 | 本地编排：调度和执行在 Mac 上 | 邮件仍会到达模型厂商 |
| 起草在 P1，预览后才交接 | 默认 L2 备好草稿，不自动打开撰写窗口 | 主动服务是核心价值 |
| 数据去向主要写在设置里 | 单封标签进入 P0 | 必须指出该封邮件的厂商 |
| 入站调用可使用查找和写意图工具 | 入站调用无工具权限，输出只有分拣或草稿 | 不可信来信不能驱动 Agent |

用户主动的历史查找和增删改，仍只使用 Mailpipe 的受限工具。
那条路径由用户发起，不由来信触发。

## 与 PRD v0.3 的工程差异

| 原设计 | 本轮修订建议 | 原因 |
|---|---|---|
| MailKit 后续回写分类动作 | Apple Events 执行与核验 | 无公开事后回写 API |
| 自动化权限仅在 P2 申请 | P0 自动整理即申请 | 自定义邮箱和异步动作依赖桥接 |
| 在 Mail 打待处理旗标 | 待处理只在 Mailpipe 显示 | 无法可靠保存和恢复原旗标 |
| 日志与撤销在 P1 | 提前到 P0 | P0 已经自动改动邮件 |
| 按账号指定 Harness 在 P1 | 最小账户路由约束提前到 P0 | 防止回退改变数据去向 |
| 选中邮件即有摘要 | 明确 App 选中与 Mail 选中两种入口 | MailKit 无 selection API |
| 自然语言规则全部本地确定执行 | 区分字面条件和模型语义条件 | “发票”等概念需要语义判断 |
| 未纠正比例等于准确率 | 单列纠错率与标注准确率 | 未纠正不证明正确 |
| 不读取 Mail 私有数据库 | P1 可选的只读历史搜索 | 用户要在 Agent 中查历史邮件。见 O1 |
| Harness 不开放工具 | 只开放 Mailpipe 自己的受限工具 | 查找和写意图需要工具；内置工具仍禁止 |

上表最后一行只覆盖用户主动发起的 Agent。
入站邮件的收紧见上一节，不把工具权限交回来信。
待处理旗标仍然不写。
L2 可以另存一封回复草稿到草稿邮箱，那不是旗标。

## 明确不做

不做新邮件客户端、SMTP 或服务商直发。
不接管模型账户，不替用户登录 Harness。
不经 Mailpipe 的服务器转发邮件，也不另存一份云端副本。
不声称全部在本地发生，也不声称端侧 AI。
不索引整个硬盘。
不自建邮件全文或向量索引，除非 [邮件集成](mail-integration.md) 的备选条件成立。
不写入 Mail 的数据库或邮件文件。
不申请辅助功能。
历史搜索未授权时，不读取 Mail 私有库。
不把全库内容交给模型。
不通过安全扩展伪装 AI 摘要横幅。
不让不可信来信驱动 Agent、改规则或改路由。
不自动打开撰写窗口。
不将分拣或草稿直接变成发送。
不把合盖期间的处理写成已具备的能力。

## 体验成功标准（假设）

| 指标 | 设计目标 / 测量方法 |
|---|---|
| 激活 | 24 小时内完成授权并处理一封合成邮件；目标 60% |
| 分拣 | 标注样本上“要不要回复”的准确率目标 90%；同时报告样本量 |
| 该回复却未备草稿 | 单独统计假阴性；Beta 后确定可接受阈值 |
| 不该回复却备了草稿 | 单独统计误报；分拣要压住这类消耗 |
| 纠错 | 统计用户纠错率，不代替准确率 |
| 延迟 | 分列排队、调用和回写；CLI 中位目标 3 分钟 |
| 可靠性 | 失败率目标 2%；未知动作结果单列 |
| 留存 | 第 4 周仍处理邮件，目标 35% |
| 价值 | 打开 Mac 后，需回复的邮件已有草稿；比例待 Beta 重估 |
| 去向 | 每封外发模型的邮件能指出 Harness 与厂商，或明确未知 |

报价、转化与排期均待验证。
原 PRD 假设买断 29–49 美元或年费 19–29 美元。
本轮不建立支付、试用限制或收费功能。

## 推荐与重评

先证明默认草稿落点、分拣和数据去向标签，再验证是否愿意持续使用。
分类准确率不再单独当作产品完成。
若 Apple Events 定位不可靠，先做只读建议版本。
若草稿不能保留原线程，仍以菜单栏待处理交付。
未验证前，不把 iPhone 同步写进宣传。
若 Harness 不能把入站调用限制为无工具，停止该 Adapter 的自动回复。
历史库格式或 Spotlight 覆盖未验证时，不宣布历史搜索可用。
这些降级都需要重评对应范围与宣传。
