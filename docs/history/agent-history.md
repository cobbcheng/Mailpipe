## 2026-11-15：建立设计基线

关键修订：

- MailKit 负责采集，Apple Events 负责事后动作。
- 自动化权限进入 P0，而非仅在 P2 发送时申请。
- 待处理状态只在 Mailpipe 显示，不占用原旗标。
- 日志、条件撤销和账户路由约束前移到 P0。

以上是工程化设计建议，仍受 M0 门槛约束。
没有改动原 Notion 文档，没有运行真实模型或 Mail 操作。

## 2026-11-15：P1 历史搜索与受限工具

用户确认需要在 Agent 中查找历史邮件。
竞品 Mailbutler 的读库观察见 O1 与当时的 Q-17。
因此推翻“不读取 Mail 私有数据库”。

新决定：

- P1 全量读取只发生在已授权的邮件库，并且只为查询。
- 不自建索引。元数据只读查 Envelope Index。正文走 Spotlight，再读命中的 `.emlx`。
- 表结构、正文位置、Spotlight 覆盖、`-wal`、并发只读和 `V` 编号都未验证。
- 只读打开。不写 Mail 的库或邮件文件。
- 增删改仍走 MailBridge、持久意图和读回。删除只到废纸篓。P1 不发送。
- Harness 从无工具改为只可调用 Mailpipe 的读工具和意图工具。
- 内置 shell、文件系统和直接控制 Mail 仍然禁止。接入命令未验证。
- 读库是历史搜索的单独授权。默认预选邮件库文件夹，不默认全盘访问。
- 不申请辅助功能。不把全库交给模型。云端 Harness 会让命中离开本机。

`Accounts4.sqlite` 仍不读取。
P0 自动整理在身份验证完成前，仍不靠私有库定位。

## 2026-11-16：定位对齐 PRD v0.5

产品负责人确认定位变更。
分类、摘要和回复本身不再是差异点。
核心价值是本地编排，以及收信后备好回复。

新决定：

- 当时的一句话是“收信即备好回复，邮件不经我们的服务器”。同日稍后改为产品定义，短句仍作标语。见文末。
- 本地优先指 Mac 上的调度与执行，不新增云端副本，也不经中间服务器。
- 邮件内容仍会发给用户 Harness 使用的模型厂商。
- 不声称全部在本地发生，也不声称端侧 AI。
- 默认服务级别是 L2。同日稍后收窄为只落菜单栏待处理，见下一节。
- 不自动打开撰写窗口。L3 白名单延迟自动发送仍是 P2，须单独授权。
- 单封数据去向标签进入 P0。
- 分类和摘要只作为“要不要回复”的输入，分拣先于草稿。
- 入站 Harness 调用无工具权限。同日稍后写明：生成输出只能是草稿。
- 合盖不承诺处理。说法是“打开 Mac 时，回复已经备好”。
- Apple Foundation Models 预过滤、AppleScript 草稿线程和 Power Nap 触发仍未验证。

架构前提不变：只调用本机 Harness，经 CLI 或本地 HTTP。
本轮只改文档，没有改代码，也没有改 Notion 页面。

## 2026-11-16：L2 列入 P0，标题不用“本地 AI”

产品负责人补充两条决定。

- P0 是 L0、L1、L2、单封数据去向标签，以及“要不要回复”分拣。
- L2 是默认级别。
- L2 只落在菜单栏待处理。不自动打开撰写窗口。
- 发送只打开草稿，不调用 send。
- 入站调用只读、无工具。生成输出只能是草稿。
- Mail 草稿邮箱要等 M0-16。未通过前不是 P0 落点，失败也不收回 L2。
- 产品标题是“Apple Mail 主动回复助手”。
- 不用“本地 AI”，也不用“本地 AI 邮件助手”。

## 2026-11-16：产品定义

产品定义改为：帮助 Apple Mail 用户在自己的 Mac 上，收信即备好回复，借用你已经装好的 harness，邮件不经第三方服务器。
短句“收信即备好回复，邮件不经我们的服务器”仍可作标语。
范围和其他决定不变。
